# MISSION.md Format

`MISSION.md` lives at the root of the explicitly approved teaching workspace.
It captures the reason the user is learning. Every teaching decision should
trace back to this document.

## Template

```md
# Mission: {Topic}
## Why
{1-3 sentences describing the concrete real-world outcome.}

## Success looks like
- {A specific, observable thing the user can do}
- {Another specific thing}

## Constraints
- {Time, prior knowledge, learning preferences, or other bounds}

## Out of scope
- {Adjacent topics the user does not want to pursue now}
```

## Rules

- One mission per teaching workspace.
- Prefer concrete outcomes over abstract understanding.
- If the mission is vague, interview the user before writing it.
- Confirm with the user before changing an existing mission.
- Keep it short enough to act as a compass rather than a plan.
